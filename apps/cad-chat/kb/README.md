# 機構設計知識庫(apps/cad-chat/kb)

給「設計」模式的代理在執行期查的機構知識:選型計算、設計慣例、以及這些知識怎麼對應到本系統的
選型工具與標準件幾何。不是教科書——只收「代理做決定時用得到、而且容易做錯」的東西。

## 怎麼被用到

- 系統提示會把 `INDEX.md` 的清單帶進去(伺服器啟動後第一次組提示時讀檔;改了 INDEX 要重啟)。
- 代理遇到清單上的情境時用讀檔工具讀對應主題檔。主題檔的內容**不進**系統提示,加再多主題
  提示也只多一行。
- 讀取範圍硬閘(`src/server/agent/readScope.mjs`)只放行這個目錄,不放行 `apps/` 其他地方。

## 新增一個主題

1. 複製 `_TEMPLATE.md` 改名(小寫英文加連字號,如 `conveyor.md`),照標題填內容。
2. 在 `INDEX.md` 補一行 `- 檔名|主題|何時讀`。「何時讀」寫成代理看得懂的觸發情境。
3. 跑 `node --test src/server/prompt.kb.test.js`(在 `apps/cad-chat/` 下)——格式不對會指出缺哪一段。
4. 重啟伺服器。不用改任何程式。

## 寫作規則(測試會驗前兩條)

- 必要章節:`## 適用情境`、`## 計算與選型`、`## 在本系統怎麼做`、`## 做不到與要講明的事`、`## 來源與信心`。
- `INDEX.md` 列的檔都要存在;這個目錄下的主題檔都要被 `INDEX.md` 列到。
- 數字給**典型範圍**並標出處或「經驗值」;廠商型號專屬的值(額定負荷、容許轉速)叫代理以型錄為準,
  不要寫死一個看起來很精確的數。
- 「在本系統怎麼做」只能引用實際存在的能力(選型工具的輸入欄位、`cadpy.parts` 的函式、`models/`
  下的參考模型)。能力有界線就寫出界線(目錄只有哪些型號、哪些幾何是簡化替身)。
- 「做不到與要講明的事」必填:本系統驗的是幾何(有效實體、干涉、運動掃掠),**不驗**強度、壽命、
  剛性、公差、氣壓迴路。算出來的選型依據是估算,代理要在回覆裡把假設講出來。
- 寫給代理看,不是寫給使用者看:可以用工具名與檔名;代理對使用者說話時另有措辭規則。
