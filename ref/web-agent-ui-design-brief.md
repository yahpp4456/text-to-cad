# 設計需求文件：網頁版「對話式 CAD 產圖」

> 用途：交給 UI/UX 設計（Claude design）使用。
> 本文聚焦「**使用者送出需求之後，AI 會做什麼、有哪些階段、每個階段使用者該看到什麼、需要哪些 UI**」。
> 後端架構只給最小背景，不是設計重點。

---

## 0. 一句話產品定義

把現在「開 Claude Code 打指令產 CAD 圖」的流程，搬進一個**單人本機網頁**：
使用者在瀏覽器用自然語言描述零件 → 看著 AI 一步步思考與動手 → 產出的 3D CAD 模型即時出現在畫面上 → 用文字、點選幾何或拉參數來迭代。

- **使用情境**：單人、本機、信任環境（沒有多人協作、認證、沙箱需求）。
- **目標使用者**：CAD／機構工程師。懂規格與公差、要看 3D、習慣反覆迭代。
- **取代對象**：取代「開終端機跟 Claude Code 對話」。所以體驗要比終端機**更直覺、更可視、更可控**，而不是只把聊天框搬上網頁。

---

## 1. 核心體驗（一句話流程）

```
打字描述零件  →  看 AI 思考 + 逐步動作  →  3D 模型出現  →  迭代（文字 / 點選幾何 / 調參數）
```

設計成敗的關鍵：**AI 工作過程是透明、可讀、可中斷的**。使用者要隨時知道「AI 現在在做什麼、做到哪一步、結果有沒有通過檢查」，而不是對著一個轉圈圈的 loading。

---

## 2. 建議畫面分區

五個區域。設計者可重新編排，但這五種資訊都要有家。

```
┌──────────────────────────────────────────────────────────────┐
│  D. 階段進度列 (Stage Stepper) — 理解 ▸ 規劃 ▸ 生成 ▸ 驗證 ▸ 呈現   │
├───────────────────────────┬──────────────────────────────────┤
│                           │                                  │
│   A. 對話區                │   B. 3D 檢視 / 產物畫布            │
│   (Conversation)          │   (Canvas)                       │
│   - 使用者訊息             │   - 旋轉/縮放 3D 模型              │
│   - AI 回應(串流)          │   - 點選面/邊 → 帶入對話          │
│   - tool-call 進度卡       │   - 標註/畫線                    │
│   - 澄清問答卡             │                                  │
│   - 產物卡(縮圖+下載)      ├──────────────────────────────────┤
│                           │   E. 參數控制 (Params)            │
│                           │   - 滑桿/數值（已存在於 viewer）   │
├───────────────────────────┴──────────────────────────────────┤
│  C. 產物與版本 (Artifacts / Versions) — v1 v2 v3… 可對比/回退    │
└──────────────────────────────────────────────────────────────┘
```

> 註：B、E（3D 檢視 + 參數滑桿）已經存在於現有 viewer，設計可沿用其視覺語言；A、C、D 是要**新增**的對話／產物／進度體驗，是設計重點。

## 3. ★ AI 在使用者送出需求之後做的事（階段模型）★

> 這是本文最重要的一節。AI 不是「一次回一段文字」，而是走一條多階段流水線，**中間會自我檢查、會自我修正、必要時會回頭問你**。每個階段都要有對應的 UI 呈現。
>
> 並非每次都跑完全部階段：標示「條件性」的階段只在需要時出現。

### Stage 0 — 接收與理解 (Understand)
- **AI 做什麼**：解析自然語言，抽出零件類型、尺寸、標準、材料、配合/公差、用途；判斷這是「單一零件 / 組合件 / 2D 工程圖 / 機構 / 標準件」哪一類。
- **使用者看到**：送出後 AI 立刻進入「理解中」，並回拋它抓到的關鍵規格（例如以可點選的 chips 呈現：`外徑 20mm`、`材質 鋁`、`含 M4 螺孔`）。
- **需要的 UI**：輸入框、AI 規格摘要卡（規格 chips 可點擊修正）。

### Stage 1 — 澄清 (Clarify)〔條件性〕
- **AI 做什麼**：規格不足時主動提問（例：沒給內徑、壁厚、公差等級、依據哪個標準）。一次把關鍵缺口問完，並附**建議預設值**。
- **使用者看到**：AI 的提問，最好是「快速選項 + 自由輸入」並存；能一鍵「用建議預設值繼續」。
- **需要的 UI**：問答卡（選項按鈕 + 輸入框 + 「採用預設」捷徑）。

### Stage 2 — 規劃 (Plan)
- **AI 做什麼**：決定執行路徑——要不要先拉標準件、用參數化方式生成、是否為組合件、之後要不要轉 2D 圖／切片。對外宣告計畫。
- **使用者看到**：一段簡短「我打算這樣做」的步驟清單（預設折疊，可展開）。
- **需要的 UI**：計畫步驟預覽（會餵給頂部的階段進度列 D）。

### Stage 3 — 取得標準件 (Source Parts)〔條件性〕
- **AI 做什麼**：下載標準件 STEP（軸承、螺絲、鋁擠型材…），附來源與規格。
- **使用者看到**：「正在取得 SKF 6204 軸承…」附縮圖、標準編號、狀態。
- **需要的 UI**：tool-call 進度卡（部件名 / 標準 / 縮圖 / 成功或失敗）。

### Stage 4 — 生成 (Generate)
- **AI 做什麼**：撰寫參數化建模程式 → 執行 → 產出 **STEP + GLB**（2D 路徑則產 **DXF**）。
- **使用者看到**：串流呈現「撰寫幾何 → 執行 → 產出 `part.step`」；可選擇展開看實際程式碼與執行 log。
- **需要的 UI**：生成中進度卡（可展開：原始碼 / log）。這是耗時較久的階段（數秒～分鐘級），進度回饋要扎實，不能像當機。

### Stage 5 — 檢查與自我修正 (Validate & Self-heal)
- **AI 做什麼**：跑幾何檢查——封閉性 (watertight)、自交、零件**干涉**、機構**運動掃掠干涉 (motion sweep)**、拓撲檢視。**若失敗 → 自動調參數重生**，形成修正迴圈，並把原因顯示出來。
- **使用者看到**：逐項驗證清單（✓ / ✗）；若觸發重試，顯示「偵測到干涉 → 調整 X → 重新生成」。
- **需要的 UI**：驗證結果卡（checklist 形式）＋ 重試時的原因/差異說明。
- **為何重要**：這是這個產品「比一般 text-to-CAD 可信」的核心賣點——AI 會自己抓錯並修，使用者要**看得到這份信任**。

### Stage 6 — 呈現 (Present)
- **AI 做什麼**：截圖快照 + 自動把最新產物載入 3D 畫布。
- **使用者看到**：3D 模型出現、可旋轉縮放，附規格摘要與下載入口。
- **需要的 UI**：Canvas 載入最新產物、產物卡（縮圖 + 格式標籤 + 下載）。

### Stage 7 — 迭代 (Iterate)
- **AI 做什麼**：接收回饋並改參數或重生，產生**新版本**。回饋有三種來源：
  1. 純文字（「孔再大 0.5mm」）
  2. 使用者在 3D **點選某個面/邊**，把該幾何當作參考帶入對話（「這個面倒角」）
  3. 直接拖動參數滑桿
- **使用者看到**：版本歷史、可在版本間切換/對比/回退。
- **需要的 UI**：版本時間軸（C 區）、「點選幾何 → 帶入對話」的橋接互動、參數滑桿（E 區，已存在）。

### Stage 8 — 下游／匯出 (Downstream)〔條件性〕
- **AI 做什麼**：出 2D DXF 給雷射切割、製造預檢、切片/列印。
- **使用者看到**：匯出選項與製造可行性預檢結果。
- **需要的 UI**：匯出/製造動作列（含預檢通過與否）。

---

## 4. 要設計的狀態清單 (States)

對話與產物在不同時刻長相不同，請為以下每個狀態定義視覺：

| 狀態 | 觸發時機 | 設計重點 |
|---|---|---|
| `idle` | 等待輸入 | 引導語、範例提示（empty state） |
| `understanding` | 剛送出 | 即時回饋「收到，理解中」 |
| `asking` | 需澄清 | 問答卡，不打斷對話節奏 |
| `planning` | 宣告計畫 | 可折疊步驟列 |
| `running-tool` | 取件/執行中 | tool-call 卡 + 進度 |
| `generating` | 建模中 | 耗時，扎實進度（可展開細節） |
| `validating` | 驗證中 | checklist 逐項點亮 |
| `retrying` | 驗證失敗自修 | 顯示原因 + 「重生第 N 次」 |
| `success` | 產出完成 | 產物卡 + 3D 載入 + 慶祝感（克制） |
| `error` | 無法完成 | 清楚原因 + 可重試/可改述 |
| `iterating` | 使用者回饋中 | 版本對比、變更高亮 |

## 5. 要設計的核心元件

1. **訊息泡泡**：使用者 / AI / 系統三型。
2. **tool-call 卡**：顯示「呼叫了哪個工具、輸入、狀態、產物」，可展開看細節（程式碼 / log）。設計成「可讀但不喧賓奪主」。
3. **階段進度列 (Stepper)**：頂部，反映 Stage 0–8 目前到哪、哪些已過、哪些跳過。
4. **規格 chips**：AI 抓到的規格，可點擊修正。
5. **澄清問答卡**：選項 + 自由輸入 + 採用預設。
6. **驗證結果卡 (checklist)**：watertight / 無干涉 / 運動安全… 逐項 ✓✗。
7. **產物卡**：縮圖 + 格式標籤（STEP/GLB/DXF）+ 下載 + 「在 3D 開啟」。
8. **版本時間軸**：v1→v2→v3，可切換/對比/回退。
9. **幾何→對話 橋接**：在 3D 點選面/邊，生成一個可帶入聊天的參考標記。
10. **參數面板**：滑桿/數值（沿用現有 viewer 視覺）。

---

## 6. 關鍵互動原則（給設計者的取捨提示）

- **過程透明 > 結果單張**：使用者要信任 AI 的圖，就得看到它如何驗證與修正。別把過程藏成一個 spinner。
- **可中斷**：長任務（生成/驗證）要能停止或修改方向。
- **三種迭代入口並重**：文字、點選 3D 幾何、拉參數滑桿——三者要能無縫接力，且都收斂到「產生新版本」。
- **規格永遠可見可改**：AI 對需求的理解（chips）要一直看得到、隨時可修，避免「AI 誤解了還悶頭做完」。
- **克制的 AI 語氣**：工程使用者要精確與效率，不要過度寒暄。

---

## 7. 非目標（這版不做）

- 多人協作、即時同編。
- 登入/認證/權限。
- 雲端多租戶與沙箱隔離（單人本機信任環境）。
- 行動裝置優先（以桌面寬螢幕為主）。

---

## 8. 後端資料流（背景，非設計重點）

```
瀏覽器 (對話 UI)
  └─ 訊息 ──串流──> 本機 Agent 服務 (Claude Agent SDK 掛載既有 CAD skills)
                       └─ 依 SKILL.md 呼叫 Python CLI 產圖
                              └─ 產物寫入 models/<session>/
                                     └─ viewer 既有檔案監看自動載入 3D 畫布
```

設計者只需知道：**AI 的「思考、工具呼叫、產物、驗證結果」都是逐步串流回前端的事件**，UI 要能即時呈現這條時間線，而不是等一個最終結果一次到位。

---

## 9. 給 Claude design 的具體任務

1. 設計上述五分區的桌面寬螢幕佈局（A 對話 / B 3D / C 版本 / D 階段列 / E 參數）。
2. 設計第 3 節各 AI 階段對應的對話流 UI（特別是 tool-call 卡、驗證 checklist、自我修正重試）。
3. 設計第 4 節所有狀態的視覺。
4. 設計三種迭代入口（文字 / 點選幾何 / 參數滑桿）如何收斂成版本。
5. 提供 empty state（idle）與第一次使用的引導。
6. 設計「物件屬性面板 / 規格摘要 / BOM / 2D 圖層圖例」——依第 10 節的屬性資料模型，並區分「對使用者顯示」與「內部不顯示」的欄位。

## 10. 圖面物件屬性（Object Properties / Data Model）

> 這節列出**一個 CAD 物件 / 一張圖面實際攜帶的屬性**，給設計者用來設計「屬性面板、規格摘要、BOM、標註、2D 圖層圖例、版本溯源」。
> 欄位名以系統實際輸出為準（非臆測）。
> **重要分流**：屬性分「★ 應顯示給使用者」與「⚙ 內部機制用、不該當屬性顯示」兩種——後者是「點選面/邊」「3D 渲染」背後的管線，設計時當作機制、不要塞進屬性面板。

### 10.1 物件階層（屬性面板的樹狀骨架）
組合件 → 零件 (occurrence) → 形狀 (shape) → 面 / 邊 / 頂點。

- ★ `name`（使用者命名）、`sourceName`（源碼命名）、`path`（階層路徑）、`parentId`（父層）、`kind`（solid / sheet）
- ⚙ `id`（#o1.2 選擇器 id）、`transform`（4×4 矩陣）、`shapeStart/faceStart/edgeStart` 等索引、`ordinal`

### 10.2 整體物理屬性（規格摘要 / 標題欄）
- ★ `bbox`（外形尺寸 X×Y×Z，可換算「長寬高」）、`volume`（體積）、`area`（表面積）、`center`（重心位置）
- ★ 統計：`shapeCount` / `faceCount` / `edgeCount` / `vertexCount`、是否實心 (solid) / watertight
- ⚠ **沒有的**：`mass`（質量，需密度才能算）、`material`（生成件無材質）、公差 / 表面處理——見 10.8 缺口

### 10.3 面屬性（點選面 → 標註 / 倒角 / 帶入對話）
- ★ `surfaceType`（plane / cylinder / sphere / cone / torus / bezier…）、`area`（mm²）、`normal`（法向量）、`center`、`params`（如圓柱半徑 radius、軸 axis、原點 origin）
- ⚙ `flags`（DEGENERATE / SEAM / BOUNDARY）、`relevance`、`triangleStart/Count`

### 10.4 邊屬性（點選邊 → 倒角 / 圓角 / 標註）
- ★ `curveType`（line / circle / ellipse / parabola / hyperbola / bezier…）、`length`（mm）、`params`（半徑、中心、長短軸…）、`dihedralDeg`（二面角）、`continuity`（C0/G1/C1…）、`visibilityClass`（feature / tangent / seam / boundary…）
- ⚙ `segmentStart/Count`、`surfaceHalfEdgeStart/Count`、`flags`

### 10.5 裝配關係屬性（組合樹 / 配對清單）
- ★ `label`、`type` / `relation`（coincident / parallel / perpendicular / fixed…）、`parameters`（距離 / 角度）、固定端 vs 移動端
- ⚙ mate `id`（#m1）、端點詳細座標

### 10.6 標準件 / BOM 屬性（BOM 表 / 零件卡）
- ★ `series`、`model`、`standard`（如 ISO 4762）、`category`、`family`、`material`、關鍵尺寸（bore / rod_dia / thread / lengthMm…）、`source`（來源）、`confidence`（low/med/high）
- ★ 下載溯源：`stepUrl`、`sha256`

### 10.7 2D 圖面（DXF）屬性（2D 視圖 / 雷切圖層圖例）
- ★ `layer`（圖層名）、`kind`（cut 切割 / bend 折彎，由圖層自動判定）、實體型別（LINE / ARC / CIRCLE / LWPOLYLINE）、單位（mm，1:1）、整體 bbox、各型別實體計數
- 幾何：line 的 start/end、arc 的 center/radius/角度、circle 的 center/radius

### 10.8 來源 / 版本 / 驗證屬性（版本時間軸 / 溯源 / 信任）
- ★ 溯源：`generator`、`sourcePath`、`sourceHash`、`generatedAt`、檔案 `outputs`（path + kind: step/stl/glb…）、生成 `status`（running / finished）
- ★ 驗證結果（呼應 Stage 5）：watertight、自交、零件干涉、運動掃掠干涉、網格品質——逐項 ✓/✗ 與原因

### 10.9 ⚠ 目前 pipeline 缺少的屬性（設計時要決策）
這些是工程圖常見、但系統**現在沒有穩定提供**的屬性。設計時請決定「這版不放 / 留欄位待補 / 標示 N/A」：
- **質量 (mass)**：只有體積，需材質密度才能算。
- **材質 (material)**：**只有標準件有**，自己生成的零件無。
- **公差 / 配合 / GD&T**：非一等公民，目前不存在於屬性中。
- **表面處理 / 粗糙度**：無。
- **數量 (qty) / 件號 (item no.)**：BOM 需要，目前無彙總層。

> 設計建議：屬性面板分「**幾何衍生（一定有，可信）**」與「**工程標註（可能缺，標 N/A 或留待補）**」兩組，避免讓使用者誤以為缺的欄位是 AI 漏算。
